# G3a：学生学到不同阶段，老师该怎么教？

我们想知道：学生刚开始学时，多给解题过程是否有用？学生已经学了一段时间后，最有用的教法会不会改变？

大模型当老师，小模型当学生。学生先自己作答，再根据老师的输出反馈学习；老师本身不更新。额外提示只给老师看，学生做题时仍只看原题，原响应token和mask保持不变。

## 怎么比较

做K&K真假话逻辑题和GSM8K数学应用题。每类题先正常训练150步，在第30、90步各保存学生的模型、优化器和训练状态。然后从每份存档各开四条对比，每条再训练150步。

例如“30步存档＋只给答案”是拿训练了30步的学生，给老师看正确答案，再让学生继续学150步，最后到180步。90步存档出发则到240步。

| 教法 | 老师额外看到什么 | 想比较什么 |
|---|---|---|
| 不给提示（plain OPD） | 无额外提示 | 其他教法与它比较 |
| 只给答案 | 正确答案 | 答案本身有多少帮助 |
| 完整解法 | 正确答案和解题过程 | 多给过程是否更好 |
| 针对错误给提示 | 正确答案、能核验的错因与修正提示 | 针对错误是否更有效 |

完整解法和错误提示共享答案权限。错误无法机械核验时，按冻结规则回退为只给答案，并记录原因；不删除这条轨迹，也不声称定位了自由思维链的首错。

同一起点的四组使用共同的追加题序、相同学习率和训练步数，保留该起点的优化器状态。正常分叉时重置共同sampler；跨机器接续已经开始的分支时恢复其sampler/RNG，不重新分叉。

## 当前范围与配置

当前执行的是 `configs/core18-scope.json`：2个任务、1个训练种子、2个起点、4种教法。共2条准备训练与16条正式追加分支。Zebra、Countdown、种子43/44和关键步骤不在当前队列中。

| 设置 | 固定值 |
|---|---|
| 老师 / 学生 | Qwen3-8B固定 / Qwen3-1.7B-Base更新 |
| 每步题数 / 每题回答数 | 128 / 8 |
| mini batch / 每卡micro batch | 16 / 1 |
| 学习率 | 1e-6 |
| 输出上限 | K&K 4096，GSM8K 8192 token |
| 提示长度上限 | 两任务均4096，来自全量冻结审计 |
| 参考训练 / 每个分支追加 | 150步 / 150步 |
| 并行 | 8张GPU，两条路线各4张独占 |

`protocol-baseline.json`保留最初的全矩阵协议作为来源；**实际调度以core18范围文件为准**。准备工具会写入匹配的协议SHA，不会把旧132条全矩阵直接作为当前运行任务。

## 数据与测验

K&K：训练20000题、诊断128题、开发512题、终测1024题。GSM8K：官方训练集划分为训练6833题、诊断128题、开发512题；官方测试1319题保持独立。MATH-500的500题仅用于GSM分支终点迁移测试。

训练过程中每25步用512题、每题8次回答测一次。pass@1是单次平均正确率，pass@8是8次里至少答对一次的题目比例。50/100/150步记录结果、回答长度和触及输出上限的比例。训练reward与开发正确率分开。

正式终测只看预定终点，每题32次，采样种子42–73、temperature 0.7、top-p 0.8、top-k 20。前后诊断用128题×16次，采样种子分别为2000–2015和3000–3015。固定终点，不挑中途较好checkpoint，不用终测调参。

分析报告所有k=1–32、逐题配对bootstrap和“学生起点×指导”的差异。当前只有一个训练种子，题目bootstrap不能代表换训练种子后的波动。两个学生状态若没有明显区分，或训练尚未平台化，要如实报告。

正式训练前的两项一次性OPD更新/续训检查属于运行验收，计入成本，不计入18条科学路线。训练结束后还需独立评测、诊断和分析；`training_complete`不等于整项研究完成。
